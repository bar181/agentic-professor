# AMCD Quick Guide
## The CORE + FLEX Approach to Course Design

---

## What is AMCD?

**Adaptive Modular Course Design** is a framework for creating technical education that serves diverse audiences from a single, well-designed foundation.

**The Key Insight**: Don't create separate courses for different skill levels. Instead, create one excellent **CORE** and multiple **FLEX** options.

---

## The CORE + FLEX Model

### CORE = What Stays Constant

Four lessons that every learner experiences, regardless of skill level:

```
┌─────┬─────────────┬────────────────────────────────────────────┐
│     │ LESSON      │ WHAT TO DO                                 │
├─────┼─────────────┼────────────────────────────────────────────┤
│  C  │ CAPTIVATE   │ Hook them. Tell a story. Show why it       │
│     │             │ matters. Use analogies. High energy.       │
│     │             │ NO jargon, NO code yet.                    │
├─────┼─────────────┼────────────────────────────────────────────┤
│  O  │ ORIENT      │ Explain the concepts. Be systematic.       │
│     │             │ Define terms. Use diagrams. Progress       │
│     │             │ from simple to complex. Calm energy.       │
├─────┼─────────────┼────────────────────────────────────────────┤
│  R  │ REALIZE     │ Show a real case study. Name the hero.     │
│     │             │ Present the problem, constraints, decision.│
│     │             │ Ask "what would you do?" Warm energy.      │
├─────┼─────────────┼────────────────────────────────────────────┤
│  E  │ EXECUTE     │ Hands-on demo. Show your work. Make        │
│     │             │ mistakes ON PURPOSE and fix them.          │
│     │             │ Share shortcuts. Focused energy.           │
└─────┴─────────────┴────────────────────────────────────────────┘
```

### FLEX = What Adapts

Problem sets that change based on audience:

```
┌─────┬─────────────┬────────────────────────────────────────────┐
│     │ PRINCIPLE   │ HOW TO APPLY IT                            │
├─────┼─────────────┼────────────────────────────────────────────┤
│  F  │ FIT         │ Match difficulty to the learner.           │
│     │             │ Beginners get scaffolding.                 │
│     │             │ Experts get open-ended challenges.         │
├─────┼─────────────┼────────────────────────────────────────────┤
│  L  │ LEVEL       │ Create 2-3 tiers. Not more.                │
│     │             │ Examples: Less/Standard/More               │
│     │             │ Or: Executive/Practitioner/Technical       │
├─────┼─────────────┼────────────────────────────────────────────┤
│  E  │ EQUIVALENT  │ Each tier takes the SAME TIME.             │
│     │             │ Beginner on "Less" = 45 min                │
│     │             │ Expert on "More" = 45 min                  │
├─────┼─────────────┼────────────────────────────────────────────┤
│  X  │ EXPAND      │ Stack modules into pathways.               │
│     │             │ Stack pathways into courses.               │
│     │             │ Add projects at each level.                │
└─────┴─────────────┴────────────────────────────────────────────┘
```

## Step-by-Step: Building Your First Module

### Step 1: Define the North Star (5 minutes)

Write ONE sentence describing what learners will achieve:

> "By completing this module, learners will be able to [VERB] [OUTCOME] so that [REAL-WORLD BENEFIT]."

Example:
> "By completing this module, learners will be able to **design a normalized database schema** so that **their applications can scale without data integrity issues**."

### Step 2: Write the CORE Lessons (2-4 hours)

**Lesson 1: CAPTIVATE (400-600 words)**
- Start with a hook (story, surprising fact, provocative question)
- Use analogies to familiar concepts
- Explain why this matters in the real world
- End with a promise of what they'll achieve
- Energy: Enthusiastic, like a TED talk

**Lesson 2: ORIENT (600-800 words)**
- Define key terms on first use
- Present concepts systematically
- Use diagrams and visual aids
- Progress from simple to complex
- Energy: Calm, methodical, like a professor

**Lesson 3: REALIZE (500-700 words)**
- Tell a specific case study with a named protagonist
- Present: Problem → Constraints → Decision → Outcome
- Ask "what would you do?" before revealing the answer
- Connect to broader implications
- Energy: Warm, storytelling, like a mentor

**Lesson 4: EXECUTE (300-500 words + examples)**
- Show the actual process step by step
- Make a mistake intentionally and debug it
- Provide "pro tips" and shortcuts
- End with common errors to avoid
- Energy: Practical, direct, like a colleague

### Step 3: Design the FLEX Problem Sets (1-2 hours)

**Start with the Global Understanding section (same for all tiers):**
- Context that all learners need
- Background information
- Resources available

**Then create 2-3 tiers:**

| Tier | Target Audience | Characteristics |
|------|-----------------|-----------------|
| **Less** | Beginners | Guided steps, starter code, explicit hints |
| **Standard** | Typical learners | Clear specs, approach open |
| **More** | Advanced | Minimal guidance, edge cases, higher expectations |

**Check time equivalence:**
- Have someone at each level attempt their tier
- Adjust scope until each tier takes ~45 minutes for its target audience

### Step 4: Define the Portfolio Artifact

What tangible thing will learners create? Be specific:

❌ "Understanding of databases" (not tangible)
✅ "A normalized database schema with documentation explaining design decisions" (tangible, portfolio-worthy)

## Quick Reference: Content Specifications

### Lesson Lengths

| Lesson | Word Count | Time to Read | Video Length |
|--------|------------|--------------|--------------|
| Captivate | 400-600 | 2-3 min | 3-5 min |
| Orient | 600-800 | 4-5 min | 5-8 min |
| Realize | 500-700 | 3-4 min | 4-6 min |
| Execute | 300-500 + code | 3-4 min | 5-10 min |

### Visual Breaks

Add a visual element every 200-300 words:
- Diagram
- Table
- Callout box
- Code block
- Image

### Engagement Elements

| Section | Add This |
|---------|----------|
| Module start | Ice-breaker or poll |
| Lesson 1 | 2-3 "What if?" questions |
| Lesson 2 | Concept check after each major idea |
| Lesson 3 | "What would you do?" decision point |
| Lesson 4 | "Try it yourself" pause points |
| Problem set start | Warm-up activity |

## Scaling Up: Pathways and Courses

### Pathway (3-4 Modules)

```
Module 1: Foundation     →  Artifact 1
Module 2: Build          →  Artifact 2 (builds on 1)
Module 3: Extend         →  Artifact 3 (builds on 2)
Module 4: PROJECT        →  Pathway deliverable (synthesizes 1-3)
```

### Course (3-4 Pathways)

```
Pathway 1: Fundamentals  →  Pathway Project 1
Pathway 2: Application   →  Pathway Project 2
Pathway 3: Advanced      →  Pathway Project 3
Pathway 4: CAPSTONE      →  Course deliverable (synthesizes all)
```

## Common Mistakes to Avoid

| Mistake | Why It's Wrong | Do This Instead |
|---------|---------------|-----------------|
| **All info in Lesson 1** | Cognitive overload | Save details for Lesson 2 |
| **No story in Lesson 3** | Forgettable | Name a protagonist, show stakes |
| **Perfect code in Lesson 4** | Unrealistic | Show errors and how to fix them |
| **4+ problem set tiers** | Decision paralysis | Limit to 2-3 options |
| **Tiers with different times** | Unfair assessment | Calibrate for time equivalence |
| **Generic hero** | No connection | Make hero specific and relatable |

## Checklists

### Before Releasing a Module

**CORE Checklist:**
- [ ] North Star statement is clear and specific
- [ ] Lesson 1 has a compelling hook with no jargon
- [ ] Lesson 2 defines all terms on first use
- [ ] Lesson 3 has a named protagonist and real stakes
- [ ] Lesson 4 shows at least one error and recovery
- [ ] All lessons have visual breaks every 200-300 words

**FLEX Checklist:**
- [ ] 2-3 problem set tiers (not more)
- [ ] Global understanding section is identical across tiers
- [ ] Each tier has clear target audience
- [ ] Time equivalence validated (same time, different scope)
- [ ] Portfolio artifact is tangible and specific
- [ ] Rubric provided for each tier

## The CORE + FLEX Pitch (30 Seconds)

> "Most instructional design creates separate courses for different audiences. That's expensive and inconsistent.
>
> AMCD uses CORE + FLEX: a stable CORE of four lessons that everyone experiences—Captivate, Orient, Realize, Execute—plus FLEX problem sets that adapt to different skill levels.
>
> The result: design once, serve everyone, maintain quality."
