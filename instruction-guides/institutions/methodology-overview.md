# Methodology Overview: Understanding AMCD and CORE+FLEX

**A Technical Guide for Curriculum Committees and Instructional Designers**

---

## The Foundation: Why AMCD Exists

Traditional course design approaches face a fundamental tension:

| Approach | Strength | Weakness |
|----------|----------|----------|
| Expert-driven | High quality, authentic | Expensive, inconsistent structure |
| Template-driven | Consistent structure | Often rigid, low engagement |
| AI-generated | Fast, scalable | Generic, pedagogically weak |

AMCD resolves this tension by providing a **pedagogically-grounded structure** that AI can implement consistently while preserving the flexibility experts need.

## Theoretical Foundations

AMCD synthesizes 12 evidence-based pedagogical principles:

### Learning Science Foundations

| Principle | Source | How AMCD Applies It |
|-----------|--------|-------------------|
| **Bloom's Taxonomy** | Bloom (1956), Anderson & Krathwohl (2001) | Each lesson targets specific cognitive level; progression through module |
| **Cognitive Load Theory** | Sweller (1988, 2011) | Controlled complexity; persona-based pacing; chunked content |
| **Zone of Proximal Development** | Vygotsky (1978) | Tiered problem sets; scaffolding varies by learner level |
| **Scaffolding** | Wood, Bruner & Ross (1976) | FLEX tiers provide variable support; gradual release |

### Motivation and Engagement

| Principle | Source | How AMCD Applies It |
|-----------|--------|-------------------|
| **Self-Determination Theory** | Deci & Ryan (1985, 2000) | Autonomy in tier selection; competence through success |
| **Flow Theory** | Csikszentmihalyi (1990) | Challenge-skill balance; clear goals; immediate feedback |
| **Expectancy-Value Theory** | Eccles & Wigfield (2002) | Lesson 1 establishes value; success builds expectancy |

### Structural and Design Principles

| Principle | Source | How AMCD Applies It |
|-----------|--------|-------------------|
| **Backward Design** | Wiggins & McTighe (2005) | Start with capstone; design backward to lessons |
| **Mastery Learning** | Bloom (1968) | Problem sets ensure mastery before progression |
| **Spaced Practice** | Ebbinghaus (1885), Cepeda et al. (2006) | Spiral curriculum; concept revisitation |
| **Narrative Pedagogy** | Ironside (2006) | Hero system; case study structure |
| **Universal Design for Learning** | CAST (2018) | Multiple tiers; varied representations |

## The CORE + FLEX Model

### CORE: Four Stable Lessons Per Module

Every module follows the same four-lesson structure, each serving a distinct pedagogical purpose:

```
┌─────────────────────────────────────────────────────────────────────┐
│                        MODULE STRUCTURE                              │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐        │
│  │ LESSON 1 │ → │ LESSON 2 │ → │ LESSON 3 │ → │ LESSON 4 │        │
│  │ Captivate│   │  Orient  │   │ Realize  │   │ Execute  │        │
│  ├──────────┤   ├──────────┤   ├──────────┤   ├──────────┤        │
│  │ Hook &   │   │ Concepts │   │ Case     │   │ Hands-On │        │
│  │ Relevance│   │ & Theory │   │ Study    │   │ Practice │        │
│  ├──────────┤   ├──────────┤   ├──────────┤   ├──────────┤        │
│  │ Why      │   │ How      │   │ When     │   │ Do       │        │
│  │ care?    │   │ works?   │   │ applies? │   │ it!      │        │
│  ├──────────┤   ├──────────┤   ├──────────┤   ├──────────┤        │
│  │ Energy:  │   │ Energy:  │   │ Energy:  │   │ Energy:  │        │
│  │ 7/10     │   │ 5/10     │   │ 6/10     │   │ 4/10     │        │
│  └──────────┘   └──────────┘   └──────────┘   └──────────┘        │
│                                                                      │
│                    ↓ FLEX Problem Sets ↓                             │
│                                                                      │
│  ┌──────────────────────────────────────────────────────────────┐   │
│  │  Tier 1:     Tier 2:      Tier 3:       Tier 4:             │   │
│  │  Foundation  Standard     Advanced      Hacker (optional)   │   │
│  │  (Guided)    (Scaffolded) (Independent) (Open-ended)        │   │
│  └──────────────────────────────────────────────────────────────┘   │
│                                                                      │
│  All tiers target ~45 minutes (Time Equivalence Principle)          │
│                                                                      │
└─────────────────────────────────────────────────────────────────────┘
```

### Lesson 1: Captivate (Why Should I Care?)

**Pedagogical Purpose**: Create emotional and intellectual engagement before teaching

| Aspect | Specification |
|--------|--------------|
| Word Count | 400-600 words |
| Energy Level | 7/10 (enthusiastic, warm) |
| Bloom's Target | Remember/Understand |
| Key Elements | Hook, analogy, stakes, preview |
| Persona | "The Captivating Storyteller" |

**Instructional Rationale**: Research on motivation (Expectancy-Value Theory) demonstrates that perceived value precedes engagement. Lesson 1 establishes why the content matters before explaining how it works.

### Lesson 2: Orient (How Does This Work?)

**Pedagogical Purpose**: Build systematic understanding through clear explanation

| Aspect | Specification |
|--------|--------------|
| Word Count | 600-800 words |
| Energy Level | 5/10 (calm, methodical) |
| Bloom's Target | Understand/Apply |
| Key Elements | Definitions, examples, patterns, misconceptions |
| Persona | "The Patient Systematizer" |

**Instructional Rationale**: Cognitive Load Theory emphasizes the importance of structured, progressive explanation. Lesson 2 provides the conceptual foundation with examples that build from simple to complex.

### Lesson 3: Realize (When Does This Apply?)

**Pedagogical Purpose**: Demonstrate application through narrative case study

| Aspect | Specification |
|--------|--------------|
| Word Count | 500-700 words |
| Energy Level | 6/10 (engaged, warm) |
| Bloom's Target | Apply/Analyze |
| Key Elements | Hero character, dilemma, decision, consequences |
| Persona | "The Empathetic Navigator" |

**Instructional Rationale**: Narrative pedagogy research shows stories increase retention and transfer. The hero character provides a consistent thread throughout the course and models the thinking process.

### Lesson 4: Execute (How Do I Do This?)

**Pedagogical Purpose**: Enable skill application through guided practice

| Aspect | Specification |
|--------|--------------|
| Word Count | 300-500 words (instruction) |
| Energy Level | 4/10 (direct, focused) |
| Bloom's Target | Evaluate/Create |
| Key Elements | Clear task, success criteria, error anticipation |
| Persona | "The Focused Coach" |

**Instructional Rationale**: Constructivist learning theory emphasizes that learners must build knowledge through doing. Lesson 4 provides the structured opportunity for application.

## FLEX: Tiered Problem Sets

### The Time Equivalence Principle

All problem set tiers target the same time investment (~45 minutes). Difficulty varies through scaffolding, not scope.

| Tier | Target Learner | Scaffolding Level | Starter Code |
|------|---------------|-------------------|--------------|
| Tier 1: Foundation | New to concept | Step-by-step guidance | 70-80% provided |
| Tier 2: Standard | Has foundation | Milestone guidance | 40-50% provided |
| Tier 3: Advanced | Confident | Requirements only | 0-20% provided |
| Tier 4: Hacker | Expert | Open-ended | None |

**Why This Matters**:
- Fairness: All learners invest equal time
- Grading: Equivalent effort regardless of tier
- Growth: Learners can move between tiers as capability develops

### Scaffolding Design

```
            SCAFFOLDING SPECTRUM

High Support ─────────────────────────────► Low Support

TIER 1         TIER 2          TIER 3         TIER 4
┌────────┐    ┌────────┐      ┌────────┐     ┌────────┐
│Step 1  │    │Goal 1  │      │Req 1   │     │Challenge│
│Step 2  │    │Goal 2  │      │Req 2   │     │         │
│Step 3  │    │        │      │        │     │Constraints│
│Check   │    │Hints   │      │Success │     │only     │
│Step 4  │    │(hidden)│      │Criteria│     │         │
│...     │    │        │      │        │     │         │
└────────┘    └────────┘      └────────┘     └────────┘

~45 min        ~45 min         ~45 min        ~45 min
```

## Course Architecture

### Hierarchy

```
COURSE
├── Pathway 1 (Thematic grouping)
│   ├── Module 1.1
│   │   ├── CORE Lessons (4)
│   │   └── FLEX Problem Sets (2-4 tiers)
│   ├── Module 1.2
│   ├── Module 1.3
│   ├── Module 1.4
│   └── Mini-Capstone
├── Pathway 2
│   ├── Module 2.1
│   ├── ...
│   └── Mini-Capstone
├── Pathway 3
│   └── ...
└── Course Capstone
```

### Backward Design Implementation

```
DESIGN SEQUENCE (Backward):

1. Define Course Capstone
   └── What should learners be able to do?

2. Derive Pathway Outcomes
   └── What capabilities compose the capstone?

3. Design Module Objectives
   └── What must learners know for pathway outcomes?

4. Generate CORE Lessons
   └── What instruction leads to objectives?

5. Create FLEX Problem Sets
   └── How will learners practice and prove mastery?
```

## Quality Assurance

### Scoring System

Each piece of generated content is evaluated against a rubric:

| Category | Point Range | Example |
|----------|-------------|---------|
| Major Positives | +10 to +20 | Opens with resonant hook |
| Moderate Positives | +5 to +9 | Uses effective analogies |
| Minor Positives | +1 to +4 | Appropriate word count |
| Major Negatives | -10 to -20 | Uses undefined jargon |
| Moderate Negatives | -5 to -9 | Missing transitions |
| Minor Negatives | -1 to -4 | Slightly off word count |

**Thresholds**:
- 90+: Auto-approve
- 80-89: Minor revisions
- 70-79: Regenerate with feedback
- <70: Human review required

### Institutional Compliance Scorecard

The system generates a compliance scorecard showing:

- Structure compliance (all modules have 4 CORE lessons)
- Word count compliance (all lessons within range)
- Voice consistency (persona adherence)
- Bloom's progression (cognitive level alignment)
- Portfolio artifacts (deliverables defined)
- Time equivalence (all tiers target same duration)

## Comparison with Other Approaches

| Approach | Structure | Consistency | Speed | Quality Control |
|----------|-----------|-------------|-------|----------------|
| ADDIE | Process model | Variable | Slow | Depends on designer |
| SAM | Iterative | Variable | Medium | Built-in review |
| AMCD | Content model | High | Fast (with AI) | Automated + human |

**Key Distinction**: AMCD is a **content structure model** that complements process models like ADDIE or SAM. It defines what goes in each lesson, not how to manage the project.
