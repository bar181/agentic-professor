## The Batch Creation Method

Instead of creating courses linearly (Module 1 → Module 2 → Module 3), use the AMCD structure to batch by lesson type.

### Traditional Approach

```
Week 1: Module 1 (all lessons)
Week 2: Module 2 (all lessons)
Week 3: Module 3 (all lessons)
Week 4: Module 4 (all lessons)

Problem: Constant context switching
```

### Batch Approach

```
Day 1: All Captivate outlines (Modules 1-8)
Day 2: All Orient outlines (Modules 1-8)
Day 3: All Realize outlines (Modules 1-8)
Day 4: All Execute outlines (Modules 1-8)
Days 5-8: Record all Captivates
Days 9-12: Record all Orients
...

Benefit: Same mental mode for each batch
```

### Why Batching Works

- **Mental context stays consistent**: Writing hooks uses different brain mode than writing instructions
- **Patterns emerge**: By the 4th Captivate, you see what works
- **Faster iteration**: Fix patterns across all modules at once
- **Quality baseline rises**: Each batch gets better

## Creating Course Variants

One of AMCD's biggest advantages: **audience variants from one source**.

### The Scenario

You have a course on "Marketing for Small Business."

Your audience wants:
- Marketing for E-commerce
- Marketing for Service Businesses
- Marketing for B2B

### Traditional Approach

Create three separate courses = 3x the work

### AMCD Approach

Create one master course, then adapt:

| What Changes | What Stays |
|--------------|------------|
| Examples (e-commerce vs B2B) | CORE structure |
| Case studies (different heroes) | Core concepts |
| Execute tasks (platform-specific) | Teaching sequence |
| Terminology (industry language) | Learning objectives |

**Time to create variant: 10-20% of original**

### How to Adapt

1. **Captivate**: Change the hook story to match new audience
2. **Orient**: Keep concepts, change examples to match context
3. **Realize**: New hero from target industry
4. **Execute**: Same skills, different application context

## The Course Blueprint System

Create reusable blueprints for common course types.

### Example: Skill-Based Course Blueprint

```
Module Pattern:
- Captivate: [Hero] struggled with [common problem]. Discovery of [skill] changed everything.
- Orient: [Skill] has [3 key components]. Here's each one with examples.
- Realize: Follow [Hero] applying [skill] to real situation.
- Execute: Practice [skill] using the [provided template/tool].

Reuse for: Writing, Design, Coding, Marketing, Sales...
```

### Example: Framework Course Blueprint

```
Module Pattern:
- Captivate: The difference between [success/failure] often comes down to [framework].
- Orient: [Framework] has [N steps]: [Step 1], [Step 2], [Step 3].
- Realize: Watch [Hero] use [framework] to solve [common challenge].
- Execute: Apply [framework] to your [specific situation].

Reuse for: Decision-making, Problem-solving, Planning...
```

### Building Your Blueprint Library

1. Create your first successful course
2. Extract the patterns that worked
3. Document as reusable blueprint
4. Apply to next course
5. Refine based on results

## Quality at Scale

More courses doesn't mean worse courses if you maintain systems.

### Quality Checklist (Use for Every Module)

```
Captivate:
□ Starts with story/hook, not information
□ Stakes are clear
□ Preview promises specific outcome

Orient:
□ Every concept has an example
□ Only essential concepts included
□ Progresses simple → complex

Realize:
□ Named character with situation
□ Shows struggle before success
□ Clearly connects to Lesson 2 concepts

Execute:
□ Task is specific
□ Success criteria are observable
□ Common mistakes identified
```

### Review Before Publish

- [ ] Read Captivate aloud—does it hook?
- [ ] Check Orient examples—clear to beginner?
- [ ] Read Realize story—would you remember this?
- [ ] Try Execute task—can you complete it?

### Strategic Course Planning

```

├── Advanced Course (deeper on specific area)
├── Variation 1 (different audience)
```

## Making It Sustainable

### The Burnout Prevention Protocol

1. **Batch don't marathon**: Create in focused sessions, not all-day grinds
2. **Structure before content**: Planning prevents wasted work
3. **Good enough ships**: Perfect courses don't exist
4. **Update don't rebuild**: AMCD makes updates surgical

### Sustainable Production Schedule

```
Week 1: Plan + Captivates (focused mornings)
Week 2: Orients (focused mornings)
Week 3: Realizes + Executes (focused mornings)
Week 4: Recording/Production
Week 5: Editing + Launch Prep

One course every 4-6 weeks is sustainable
```
